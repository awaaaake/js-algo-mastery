### 문제풀이
그리디 알고리즘<BR/>
- 사전순으로 가장 빠른 방향을 먼저 시도하면서 경로를 탐색 (BFS보다 훨씬 효율적인 탐색)<BR/>
1. 사전순으로 탐색<BR/>
2. 현재위치에서 목표 위치까지의 직선거리를 계산해 남은 이동 횟수로 도착할 수 있는지 판단<BR/>
    - 각 이동은 remainK를 줄인다.<BR/>
3. 그리디 탐색: d, l, r, u 순으로 탐색하면서 사전순으로 빠른 경로를 계속 탐색한다.<BR/>
    - 남은 이동횟수와 목표위치까지의 거리가 맞아떨어지는 확인<BR/>
-> 매번 k가 1씩 줄면서, 최선의 선택을 하므로 경로를 탐색하는 시간이 O(k)<BR/>

### 💡그리디 알고리즘
문제를 해결하는 과정에서 매 순간 최적의 선택을 하는 방법<BR/>
즉, 현재 상황에서 가장 좋아보이는(이득이되는) 선택을 함으로써 전체 문제의 최적해를 찾아가는 알고리즘<BR/>
-> 매순간의 결정이 이후의 결정에 영향X 가정을 기반으로<BR/>
-> 각 단계에서 내리는 결정이 현재 시점에서의 최선이어야한다.<BR/>

### 시간초과풀이 BFS
```JS
function solution(n, m, x, y, r, c, k) {
  const board = Array.from({ length: n }, () => new Array(m).fill("."));
  board[x - 1][y - 1] = "S";
  board[r - 1][c - 1] = "E";

  const dir = {
    l: [0, -1],
    r: [0, 1],
    d: [1, 0],
    u: [-1, 0],
  };

  const queue = [[x - 1, y - 1, ""]];
  let answer = "z".repeat(k);

  while (queue.length) {
    const [i, j, path] = queue.shift();
    if (path.length > k || answer < path) continue;

    if (path.length === k && board[i][j] === "E") {
      if (answer > path) answer = path;
      continue;
    }

    for (let [ch, d] of Object.entries(dir)) {
      const ni = i + d[0];
      const nj = j + d[1];
      if (ni >= 0 && ni < n && nj >= 0 && nj < m) {
        queue.push([ni, nj, path + ch]);
      }
    }
  }

  console.log(answer);
  return answer !== "z".repeat(k) ? answer : "impossible";
}

```
BFS가 적절하지않은 이유
- 사전순으로 가장 빠른 경로를 찾아야한다는 조건이 있다.<BR/>
- k번의 이동을 각각 4가지 방향으로 시도할수있기때문에 모든 경우를 탐색하는 시간복잡다 O(4^K) -> K가 클수록 기하급수적으로 증가하여 매우 비효율적<BR/>
- 모든 경로를 다 탐색한 후 사전순으로 비교해야한다. -> 추가적인 메모리, 시간<BR/>
