### 문제풀이

그리디 + 우선순위 큐<br/>

1. 문제 요약<br/>
- N개의 사용 요청<br/>
- 요청은 시작과 끝시간의 쌍<br/>
- 항상 자리 번호가 작은것부터 할당<br/>
- 자리가 없으면 새 자리 사용<br/>
-> 빨리 끝난 자리 중 번호가 작은 자리부터 재사용<br/>

2. 정렬 전략<br/>
- 사용시간은 정해져있기 때문에, 시작 시간이 빠른것부터 정렬<br/>

3. 자료구조<br/>
- `pq`: 사용 중인 자리들 중 종료시간이 빠른것 기준으로 정렬<br/>
-> 자리가 가장 빨리 비는 순서로<br/>
- `available` " 다음 사용자의 사용 시작 시간보다 끝나는 시간이 빠른 후보들을 담음<br/>
    -> available중 번호가 가장 작은 자리를 선택<br/>
    -> cnt[seatNum]++<br/>

### 키포인트
- 그리디 알고리즘으로 현재 사용자가 선택할 수 있는 최선의 자리를 선택한다.<br/>
- 최선의 자리를 선택하는 과정은 두번의 minheap을 필요로 한다.(`1)종료시간이 빠른`, `2)번호가 작은`)<br/>
-> minheap을 재사용할 수 있는 구조로 만들어야함<br/>

### 불가능한 풀이
종료시간이 빠르면서, 번호가 작은 순으로 정렬하는 하나의 minheap을 사용한다(available 필요x)<br/>
-> 위 풀이는 잘못된 풀이<br/>

**왜?**<br/>
**현재 대기중인 사용자의 시작시간보다 빨리 끝나는 자리들을 모두 고려하지 않는다.**<br/>
-> 현재 대기중인 사용자의 시작시간과 관계없이 빨리 끝나는 자리중 번호가 가장 빠른 자리를 반환한다.<br/>
-> 현재 대기중인 사용자의 시작시간 보다 빨리 끝나는 후보들 중, 번호가 현재 top보다 더 빠른게 있을 수 있다.<br/>

1. 시작시간보다 빨리끝나는 후보들을 먼저 고르고,<br/>
2. 그 중에서 다시 번호가 빠른것을 고른다.<br/>
