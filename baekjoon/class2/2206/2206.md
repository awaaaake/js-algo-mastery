### 문제풀이

최단경로를 찾는 BFS 문제이다.<BR/>

### visited를 정의하는 법
3차원 배열을 정의하는 법: Array.from => Array.from => () => ...
```js
const visited = Array.from({ length: N }, () =>
  Array.from({ length: M }, () => [0, 0])
  //배열요소를 돌면서 별개의(같은 참조값이 아닌) [0,0]을 return
);
```
이 방식은 각 좌표마다 독립적인 [0, 0] 배열을 생성해요. Array.from()을 사용하여 (N x M) 크기의 2차원 배열을 만들고, 각 배열 요소에 새로운 [0, 0] 배열을 할당합니다.
각 좌표마다 독립된 배열이 존재하므로, 특정 좌표에서 배열을 수정하더라도 다른 좌표에는 영향을 미치지 않아요.
예를 들어, visited[0][0][0] = 1로 설정해도 다른 좌표인 visited[1][0]에는 영향을 미치지 않습니다.

⚠️ 잘못된 방식
```js
const visited2 = Array.from({ length: N }, () =>
  Array(M).fill([0, 0])
);
```
이 방식은 모든 좌표가 동일한 [0, 0] 배열을 참조하게 됩니다. `fill() 메서드`는 `배열의 모든 요소를 같은 참조값으로 채우기` 때문에, visited2 배열 내의 모든 좌표가 하나의 [0, 0] 배열을 공유하게 됩니다.
만약 특정 좌표에서 배열을 수정하면, 그 배열을 참조하고 있는 다른 좌표들도 모두 변경됩니다.
예를 들어, visited2[0][0][0] = 1로 설정하면, visited2[1][0]도 동시에 변경됩니다. 이는 모든 좌표가 동일한 [0, 0] 배열을 참조하고 있기 때문입니다.

### 왜 벽을 부순경로와 부수지않은 경로를 별도로 정의해야하는가?
특정 좌표(x,y)에 도달하기 까지 벽을 부수고온 경로가있고, 부수지않고 온 경로가 있을 텐데 두 경우가가 모두 같은 visited를 참조하게되면, 그 다음 이어지는 경로를 따질 때 `벽을 부수지않고 x,y까지온 경로`가 불리하게 된다.<br/>

-> 💡 먼저 벽을 부숴서온 경로에 의해 방문처리가 되어버리면, 벽을 부수지않고 올수있는 경로(x,y이후에 벽을 부술수있는 기회가O경로)가 차단되어버린다.

### 시간단축을 위한 방법
queue.shift()가 아닌 queue[idx]를 활용한다.
    - queue.shift()는 큐의 첫번째 요소를 제거하고 나머지요소들을 앞으로 당기는 작업이 필요하므로 O(n)의 시간복잡도를 가진다.
    - queue[idx]는 큐의 첫번째 요소를 제거하는 대신 인덱스를 사용하여 큐의 요소에 접근하므로 O(1)의 시간복잡도를 유지할 수 있다.
