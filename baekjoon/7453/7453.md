### 문제풀이

```js
const input = require("fs")
  .readFileSync("./baekjoon/example.txt")
  .toString()
  .trim()
  .split("\n")
  .map((row) => row.split(" ").map(Number));

const [n] = input.shift();
const A = [],
  B = [],
  C = [],
  D = [];

// 입력을 각 배열 A, B, C, D로 나눔
for (let i = 0; i < n; i++) {
  A.push(input[i][0]);
  B.push(input[i][1]);
  C.push(input[i][2]);
  D.push(input[i][3]);
}

const getSubSum = (arr1, arr2) => {
  const subMap = new Map();

  for (let i = 0; i < n; i++) {
    for (let j = 0; j < n; j++) {
      const sum = arr1[i] + arr2[j];
      subMap.set(sum, (subMap.get(sum) || 0) + 1);
    }
  }

  return subMap;
};

const sub1 = getSubSum(A, B);

let answer = 0;

for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    const target = -(C[i] + D[j]);
    answer += sub1.get(target) || 0;
  }
}

console.log(answer);
```
시간복잡도 : O(n^2) + O(n^2) = O(n^2)

### 시간초과가 발생한 처음풀이
```js
const input = require("fs")
  .readFileSync("./baekjoon/example.txt")
  .toString()
  .trim()
  .split("\n")
  .map((row) => row.split(" ").map(Number));

const [n] = input.shift();
const A = [],
  B = [],
  C = [],
  D = [];

// 입력을 각 배열 A, B, C, D로 나눔
for (let i = 0; i < n; i++) {
  A.push(input[i][0]);
  B.push(input[i][1]);
  C.push(input[i][2]);
  D.push(input[i][3]);
}

const getSubSum = (arr1, arr2) => {
  const subMap = new Map();

  for (let i = 0; i < n; i++) {
    for (let j = 0; j < n; j++) {
      const sum = arr1[i] + arr2[j];
      subMap.set(sum, (subMap.get(sum) || 0) + 1);
    }
  }

  return subMap;
};

const sub1 = getSubSum(A, B);
const sub2 = getSubSum(C, D);

let answer = 0;

for (let [sum1, count1] of sub1) {
  const target = -sum1;
  answer += count1 * (sub2.get(target) || 0);
}

console.log(answer);
```
시간 복잡도: O(n^2) + O(n^2) + O(n^2) = O(n^2)<br/>
> sub1의 크기가 최대 n^2

첫번째와 두번째 코드의 이론적인 시간복잡도는 모두 O(n^2)으로 동일하다.<br/>
- 정답코드에서는 배열 C,D에대해선 Map에 따로 저장하지않고, 순회하면서 바로 적절한 target값을 찾는다.<br/>
    즉, C,D를 직접 탐색하면서 sub1.get(target)을 조회하는 방식이라 실행 속도가 상대적으로 빠르다.<br/>

- 두번째 코드의 경우, n^2순회하면서 각각의 subAB와 subCD의 map을 각각 저장하고, sub1을 또한번 순회한다.<br/>
    sub1의 크기가 커질수록 루프는 오래걸린다.

### 결론

시간 복잡도가 같아도 실행 속도는 다를 수 있다.<br/>
> ``왜 같은 𝑂(𝑛2) 복잡도인데 실행 속도가 다를까?``
시간 복잡도 : 입력이 무한히 커질 때의 증가율을 나타내는 개념<br/>
하지만 현실에서는 같은 시간 복잡도를 가지더라도 다음 요소들이 실행 속도에 영향을 미칠 수 있다.<br/>

1. 상수 계수(Constant factor)<br/>
- 𝑂(𝑛2)이라도 2n^2 vs 0.5n^2 이런 차이가 나면 실행 시간이 크게 달라질 수 있음.<br/>
- 첫 번째 코드에서는 C[i] + D[j]를 계산하면서 바로 sub1.get(target)을 조회 → Map의 O(1) 조회가 빠르게 동작<br/>
- 두 번째 코드에서는 sub1.size가 커지면 루프가 길어져서 추가 연산이 많아짐.<br/>

2. 반복문에서의 불필요한 연산<br/>
- 첫 번째 코드: n^2번 반복하면서 바로 Map 조회<br/>
- 두 번째 코드: sub1.size만큼 반복 (최대 n^2) → sub2.get(target) 호출 (최대 n^2 크기) → 불필요한 반복 발생<br/>

3. 메모리 접근 패턴 (Cache 효율성)<br/>
- CPU는 연속적인 메모리 접근을 할 때 빠르게 처리할 수 있음.<br/>
- 첫 번째 코드에서는 C[i] + D[j]를 계산하면서 sub1.get(target)을 즉시 조회 → 한 번에 처리 가능<br/>
- 두 번째 코드에서는 sub1의 키들을 순차적으로 순회하면서 sub2.get(target)을 조회 → 캐시 미스(Cache Miss) 발생 가능성이 큼<br/>

4. 데이터 구조 사용 방식의 차이<br/>
- Map의 get() 연산은 O(1)이지만, 최적화 여부에 따라 오버헤드가 발생할 수 있음.<br/>
- for (let [sum1, count1] of sub1)은 sub1.size만큼 반복해야 하므로 실제 연산량이 많아질 수 있음.<br/>
